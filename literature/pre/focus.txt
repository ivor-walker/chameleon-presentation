“Focus: Querying Large Video Datasets with Low Latency and Low Cost” introduces a system designed to efficiently answer “after-the-fact” queries over large, continuously recorded video datasets. Its primary goal is to reduce the cost and latency involved in querying video streams—for instance, to identify frames with specific objects (such as cars or bags) captured over long periods—while still maintaining high accuracy.
Key Challenges

    High Computational Cost of CNNs:
    State-of-the-art convolutional neural networks (CNNs) like ResNet152 provide high accuracy in object classification but are very computationally expensive. Running these models on every video frame, either at ingest or query time, leads to prohibitive GPU costs and unacceptable latencies.

    Large Volume and Redundancy of Video Data:
    Video streams contain many frames where objects either are absent or change little between consecutive frames. This redundancy means that applying the expensive CNN on every frame is unnecessary.

    Diverse Application Requirements:
    Different application scenarios (e.g., traffic control vs. surveillance) may have varying priorities—for instance, some may tolerate higher ingest costs for lower query latency, while others require the opposite.

Core Ideas and Techniques

The Focus system introduces a two-phase approach:
1. Ingest-Time Processing:

    Cheap CNNs:
    Instead of the expensive ground-truth CNN (GT-CNN), the system uses compressed and specialized versions of CNNs during video ingestion. These networks are tailored to the specific object classes likely to appear in a given video stream. Compression techniques (such as reducing the number of convolutional layers and using lower-resolution inputs) and specialization (training models on a limited subset of classes per stream) dramatically reduce the computational cost at ingest time.

    Top-K Indexing:
    Recognizing that the cheaper CNNs may not always yield the correct highest-confidence label, Focus stores the top-K classification results for each object. The idea is that although the top answer of the cheap CNN might be incorrect, the true label (as determined by the GT-CNN) is likely to appear within these top-K results. This indexed information allows the system to later narrow the candidate frames for a query while keeping recall high.

    Ingest-Time Clustering:
    To further reduce redundant work, Focus clusters visually similar objects based on feature vectors produced by the cheap CNN. Since objects (like a car crossing an intersection) appear nearly identical in successive frames, only a single representative (the cluster centroid) is classified with the GT-CNN at query time. This clustering dramatically cuts down the number of expensive classification operations needed later.

    Parameter Tuning:
    Focus automatically selects parameters (including the cheap CNN variant, K, and the clustering distance threshold T) by trading off ingest cost and query latency while meeting user-specified accuracy targets (typically using metrics like 95% precision and recall).

2. Query-Time Processing:

    Reducing Latency:
    When a query is issued (e.g., “find frames containing cars”), the system uses the top-K ingest index to retrieve candidate clusters quickly. It then runs the GT-CNN on only the centroids of these clusters. If a cluster centroid is classified as the queried object, all frames within that cluster are returned.

    Balancing Trade-offs:
    The system can be configured in different ways depending on the application’s needs—for example, one configuration may favor minimal ingest cost (sacrificing some query speed) while another minimizes query latency at a slightly higher ingest cost.

Experimental Evaluation

The authors evaluated Focus on more than 150 hours of video from varied domains (traffic, surveillance, and news channels). The evaluation highlights include:

    GPU Cost Savings:
    Focus can reduce the GPU consumption by up to 58× compared to ingesting all video frames using an expensive CNN.

    Query Latency Improvement:
    Queries are processed up to 37× faster than a system that would classify all frames at query time.

    Trade-off Flexibility:
    By adjusting parameters, the system can be tailored to different operational scenarios. For instance, one configuration (Focus-Opt-Ingest) significantly lowers ingest costs for rarely queried videos, whereas another (Focus-Opt-Query) prioritizes very fast query responses.

    Robustness Across Settings:
    The system maintains high accuracy (even with increased precision and recall targets) and is effective across different video content types and frame sampling rates.

Contributions and Impact

The paper makes several significant contributions:

    Formulation of the Problem Space:
    It clearly defines the trade-offs between ingest cost, query latency, and accuracy (precision and recall) in the context of video analytics.

    Innovative Use of Cheap CNNs and Top-K Indexing:
    By coupling inexpensive CNNs with a top-K ingest index, Focus achieves a scalable system capable of handling large video datasets efficiently.

    Clustering to Exploit Redundancy:
    The innovative use of clustering at ingest time minimizes duplicate work at query time, leading to large reductions in latency without compromising accuracy.

    Flexible System Design:
    The architectural choices in Focus allow for automatic parameter tuning, providing "intelligent defaults" that allow the system to be customized based on cost and latency needs.

Conclusion

Focus represents a significant advancement in the realm of video analytics by demonstrating that one can achieve both low ingestion costs and low query latency without sacrificing accuracy. Its clever use of compressed, specialized CNNs, combined with top-K indexing and object clustering, provides a viable approach for real-world applications where fast and cost-effective querying of massive video datasets is essential.
